Simplification

The function whose peaks are found. The points and their neighbour graph stay the same, so switching f changes what a peak means, not which samples are neighbours. "Smoothed x2": each value averaged with its neighbours twice before peaks are found.

How many nearest points each point is linked to before peaks and saddles are found (Ours only; a point cloud's other methods use the dataset's own k). Small k: more, smaller peaks, noise shows up. Large k: fewer, broader peaks; nearby groups merge. The graph is built in Python, so only the values computed by build_data.py are offered (comparison/variants.py, K_CHOICES).

AnyEG's own filter, a different operation from peak persistence simplification: a link from a saddle to a maximum is hidden when the height difference |f(saddle) - f(maximum)| is below this value. Maxima are never removed and their regions never change; only links disappear. (Peak persistence simplification instead merges a peak into its higher neighbour and gives its points to the surviving region.) Off at 0, which is what AnyEG's released code uses.

Blue: peaks left at each noise threshold. Red: links left at each variation threshold; links (saddles) above phi are cut, which can split the graph into separate pieces. A flat stretch means the structure is stable. Click the plot to set the noise threshold, shift+click to set phi. Grey: below this file's base threshold.

Spine drawing

Every contour, peak, saddle and link stands at the height of its value, so peaks are summits and saddles are the passes between them: the climb from a saddle to its peak is the peak's persistence. Slopes: smooth rises in small steps; solid mountain fills the sides, so each colour covers the mountain up to the height of its contour, exactly the bands of the flat spine; terraces is one flat step per contour. Drag to orbit, shift-drag to pan, wheel to zoom, double-click to reset.

More drawing options

Saturated persistence, as in the paper: a link to a peak that absorbed smaller ones runs along the ridge through them (small grey dots), so a ring stays a ring after its peaks merge. Off: straight links between the peaks that are left.

Paper style: the outermost contour sits one level below the lowest shown saddle, so empty space (most of a volume, all owned by one peak) does not swell into a huge halo. Untick it to draw down to the field minimum, as the paper does.

Lays out the peaks and saddles that are left again, so their positions fit their own distances (the exported layout was made for the full graph). Used up to 150 nodes. In compare mode the two spines then no longer share positions; untick it to line them up again.

Peak profile

What sets a peak's region apart. For the selected (or hovered) peak, every dimension of the data (and the value f) gets a small histogram: blue, the points of this peak's region; grey, all points. On the right, the region's median and its 5–95 % range, and d: how far the region's mean sits from the mean of all points, in standard deviations of all points (an effect size: around 0.2 small, 0.8 large). Dimensions are sorted by |d|, so the ones that characterise this peak come first; "narrow" marks a region much more concentrated than the data.

Select a peak to see what sets its region apart.

Clustering

Ordinary clustering of the same points, to set beside the peak regions. KMeans splits the points into k groups around k centres; DBSCAN joins points that have at least "min. neighbours" others within "radius" (in units where every dimension runs from 0 to 1) and calls the rest noise. "On": all original dimensions, or the 2D positions of the data view. The agreement with the peak regions is the adjusted Rand index (1: the same grouping, 0: no better than chance); the table says which peak holds most of each cluster. Colour the data view or the scatter plot by cluster to see them.
