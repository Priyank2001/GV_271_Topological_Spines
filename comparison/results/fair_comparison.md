# AnyEG vs our pipeline: a fair comparison

Generated by `python3 -m comparison.fair` on 2026-11-23: NVIDIA GeForce RTX 3090 (cuda:1), median of 5 timed runs after a warm-up. Raw numbers: `fair_comparison.json`. Code: `comparison/fair.py`, `comparison/reference.py`.

## What is held equal

| control | how |
|---|---|
| Same order | AnyEG gets (value, index) ranks as float32; ours gets the real values and breaks ties by index, which is the same strict order. Neither method sees ties. |
| Heights for height tests | AnyEG's arc filter `[0, 20000)` measures heights, so it gets the real values, not ranks (on ranks it dropped up to 2/3 of the arcs). |
| Same graph | One neighbour structure per case, built once outside the clock and given to both. Both methods run on both grids: 14-neighbour (TTK, AnyEG's) and 6-neighbour (ours). |
| Same GPU | One device for every GPU run; CUDA is initialised before any clock starts (also inside AnyEG's own driver process). |
| Same CPU budget | CPU runs use one thread on both sides. |
| Repeated timing | One warm-up run, then the median of the repeats. Clocks stop only after results are back on the host. |
| Matched stages | *detect*: maxima + basins + saddles, host to host (AnyEG modules 1-4 incl. copies; ours: order + ascent + passes incl. copies). *post*: different work per method (AnyEG: arcs; ours: persistence, loop filter, p*). |
| Neutral yardsticks | Merge-tree fidelity and PL saddle validity need neither method; each is native to one of them (see below), so both are shown. |
| Filters separated | Ours without the loop filter and AnyEG with its own edge bundling are extra rows, so the core algorithms are compared apart from the filters. |

## Contenders

- **AnyEG original** (GPU): AnyEG's unchanged CUDA `compute()` (cudaHelper.cu) in its driver process; *detect* is the time of the `compute()` call inside that process
- **AnyEG port** (GPU): `anyeg.TorchKernels`, the PyTorch port of the same four modules (checked equal to the original)
- **AnyEG +bundling** (GPU, not timed): the port with AnyEG's own edge bundling switched on (one saddle per pair of maxima, like ours); output only
- **AnyEG uphill arcs (diagnostic)** (GPU, not timed): NOT AnyEG: the port with the arcs that leave a saddle downhill removed, to show where AnyEG's merge-tree errors come from; output only
- **Ours** (GPU): `pipeline.extremum_graph`, torch backend, as used (loop filter on, relief >= 0.5)
- **Ours no loop filter** (GPU, not timed): the same with `min_loop_relief=0`: every pass between adjacent basins; output only
- **AnyEG port CPU** (CPU): the PyTorch port on the CPU, one thread
- **Ours CPU** (CPU): `pipeline.extremum_graph`, NumPy backend, one thread

## 1. Correctness against yardsticks that need neither method

* **Merge tree**: the superlevel-set merge tree (0-dim persistence), computed from the graph and the order alone. Each method's links are replayed from the highest saddle down; a maximum is *exact* when it dies at the reference saddle. *early* = a link joins maxima whose components are still apart at that height (a false link); *late* = a merge saddle is missing. *≥1 %*: pairs with persistence at least 1 % of the value range. Ours meets this by construction (its saddles are the merge passes).
* **PL-valid**: reported saddles whose upper link has 2+ pieces on the triangulation, i.e. real critical points of the piecewise-linear field. Only on the 14-neighbour grid (the 6-neighbour grid is not a triangulation). AnyEG meets this by construction (its module 4 is this test). For ours, *merge* counts only merge-tree saddles.

AnyEG original, the CPU runs and the GPU runs give identical graphs (section 2), so only one row per algorithm is shown.

## What cannot be made equal

- *post* is different work: AnyEG traces arcs and stops; ours computes persistence, the loop filter and saturated persistence, which AnyEG does not have.
- AnyEG original runs in its own process (its `compute()` keeps global state). The process start and file exchange are excluded from *detect* (they are in the JSON as `process_and_files`), and CUDA is initialised before its clock starts. Its `compute()` still allocates and copies everything on each call, while PyTorch reuses cached GPU memory; that is part of how each is built, and is why the port is faster than the original. Loading its kernels eagerly (`CUDA_MODULE_LOADING=EAGER`) changed nothing (tested).
- Our torch backend returns to the host between its steps; AnyEG keeps everything on the GPU inside `compute()`. That is part of each implementation and is counted.
- On the 6-neighbour grid no two neighbours of a vertex are neighbours of each other, so AnyEG's upper-link test passes every candidate with 2+ higher neighbours: AnyEG is outside its design there. It is shown to separate the effect of the grid from the effect of the algorithm.
